# v0.2 证据缺口

## 1. 证据原则

状态只接受可回读、可重复、与 AC 直接对应的证据。计划、口头/AI 汇报、表存在、历史部署、旧测试数量或一次成功截图都不能替代直接验收。不确定即未完成。控制面直接回读若完整覆盖某项 AC，可以支持该项状态；原始输出/链接仍须补入最终证据包。单项已证不代表 Gate 0 完成。

## 4. 明确禁止作为补证的动作

- 不重复原任务的真实 `/lf y` 最终验收。
- 不为了补证连接办公 Node、访问其 local-only 数据或索取凭证。
- 不用 D1 表已存在、R2 bucket 已存在或 Sites 历史版本替代业务验收。
- 不用 15 张业务表为空、24h Worker events 为 0 或 saved-version 来源 commit/archive 元数据推断机器路由、部署成功、回滚或 Gate 0 已完成。
- 当前机器身份仍被 custom-private 边缘 403 阻断，不得为了补证向正式 D1 写探针。
- 不用人工流程约定冒充 GitHub 强制保护；也不得为解除套餐阻断把仓库改为公开。
- 不把本设计 PR、Proposal 草稿或 AI 结论记为实现证据。
- 不因“没有观察到错误”推断功能正确；必须有正向与必要的负向 AC。

## 5. 证据包最低结构

每次需求状态升级至少记录：需求 ID、被验收版本/commit、环境、执行者或自动化身份、步骤、预期、实际结果、时间、可回读链接/哈希、残余风险。涉及回滚时还要记录回滚前后版本和数据边界。
