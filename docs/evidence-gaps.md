# v0.2 证据缺口

## 1. 证据原则

状态只接受可回读、可重复、与 AC 直接对应的证据。计划、口头/AI 汇报、表存在、历史部署、旧测试数量或一次成功截图都不能替代直接验收。不确定即未完成。

## 2. 当前可直接引用的证据

| 证据 | 能证明 | 不能证明 |
|---|---|---|
| GitHub App 仓库回读 | 仓库为 Private、默认分支 main、当前可见提交为恢复 SHA | App 安装是否只授权该仓库、保护规则、CI、Secrets 状态 |
| 指定 tag 读取恢复文件 | tag 名称存在且当前可解析到与基线相同的恢复说明 blob | tag 对象的 annotated 元数据和未来不变性；需独立 refs 证据补齐 |
| `SERVER_RECOVERY.md` | 恢复来源、24+1 范围、排除项、恢复时扫描结论 | 当前运行环境、当前测试通过、生产数据状态 |
| `RECOVERY_MANIFEST.sha256` | 25 个受管文件的预期哈希与文件名 | 当前仓库全树没有额外文件；源服务器仍保有同一副本 |
| 恢复源码 | v0.1 的对象、协议、幂等与审批行为设计 | v0.2 的 D1/R2、Sites、发布与回滚已实现 |

## 3. 关键缺口登记

| 缺口 | 影响 | 最低补证方式 | 补证阶段 |
|---|---|---|---|
| GitHub App 安装范围不可直接回读 | WB-101 不能完整标已证 | 安装页或 App API 显示仅授权目标仓库 | 仓库治理 |
| annotated tag 元数据未被当前接口直接回读 | 恢复基线的 tag 类型证据不完整 | refs/tag 对象直接回读，记录 tag object 与 peeled commit | 设计合并前或治理阶段 |
| 当前仓库无完整 tests | WB-004 不得标已证；历史“31 个测试”不可用 | 在云端从事实源补齐可审查测试并执行，证据绑定 commit/CI run | 经授权的实现阶段 |
| 无分支保护直接证据 | WB-102 缺失 | 规则集/保护规则 API 回读与负向验证 | 仓库治理 |
| 无 Codex Cloud/CI 运行证据 | WB-103/104/105 缺失 | 环境配置回读、最小 CI run、协作规则评审 | 云开发基础设施 |
| 无 Sites/D1/R2 资源回读 | P2 均不能因历史部署判定完成 | 资源 ID、访问边界、双层身份、迁移、空白基线、回滚/恢复的直接证据 | Gate 0 |
| 当前源码仍依赖 Kanban 和 Hermes SQLite | v0.2 单一 D1 事实源与“彻底移除”尚未实现 | 代码审查、依赖扫描、负向搜索、业务 API 验收 | 产品合同实现 |
| 无端到端 Outbox/重连/对账证据 | 可靠性需求未证 | 可重复故障注入、重启、重复消息与对账验收 | 可靠性实现 |
| 无页面证据 | P5 缺失 | 绑定同一业务 API 的页面验收记录 | 产品界面实现 |
| 无云端签名包与 Release 证据 | P6 缺失 | commit→CI→包→签名验证→Release→Node 安装的完整链路 | 发布实现 |
| 无 D1 逻辑备份恢复证据 | WB-208/WB-705 缺失 | 隔离恢复演练、记录一致性校验和恢复点 | Gate 0/验收 |

## 4. 明确禁止作为补证的动作

- 不重复原任务的真实 `/lf y` 最终验收。
- 不为了补证连接办公 Node、访问其 local-only 数据或索取凭证。
- 不用 D1 表已存在、R2 bucket 已存在或 Sites 历史版本替代业务验收。
- 不把本设计 PR、Proposal 草稿或 AI 结论记为实现证据。
- 不因“没有观察到错误”推断功能正确；必须有正向与必要的负向 AC。

## 5. 证据包最低结构

每次需求状态升级至少记录：需求 ID、被验收版本/commit、环境、执行者或自动化身份、步骤、预期、实际结果、时间、可回读链接/哈希、残余风险。涉及回滚时还要记录回滚前后版本和数据边界。
