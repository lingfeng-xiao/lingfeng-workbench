# lingfeng-workbench v0.2 需求注册表

状态口径：**已证**=已有直接证据覆盖全部 AC；**矛盾**=当前事实与目标明确冲突；**不完整**=有部分直接证据但未覆盖全部 AC；**缺失**=尚无可接受直接证据。依赖中的数字均指本注册表同前缀需求。

## P0 恢复基线

### WB-001 定位 Hermes 部署副本
- 业务描述：确认唯一允许的恢复来源，避免从办公电脑或未知备份混入源码。
- 可验证 AC：恢复说明给出 Hermes 路径、恢复时间与排除来源；仓库文件可直接回读。
- 依赖：无。
- 最低证据：`SERVER_RECOVERY.md` 与对应 commit。
- 风险：来源认错导致事实源污染。
- 回滚边界：仅撤销后续设计/恢复分支，不改 Hermes 部署副本。
- 初始状态：已证。

### WB-002 恢复纯净源码包
- 业务描述：将允许范围内的运行时源码与构建元数据恢复为可审查仓库基线。
- 可验证 AC：24 个非生成运行时文件和 1 个构建元数据文件入库；排除数据库、日志、缓存、凭证和环境文件。
- 依赖：001。
- 最低证据：恢复说明、manifest、基线 commit 文件树。
- 风险：遗漏源码或夹带运行数据。
- 回滚边界：回到恢复前空仓库；不影响服务器部署副本。
- 初始状态：已证。

### WB-003 敏感信息与数据边界检查
- 业务描述：确认恢复包不携带凭证或运行数据，并记录扫描范围。
- 可验证 AC：恢复说明记录扫描规则数、命中结果和排除项；manifest 仅含允许文件。
- 依赖：002。
- 最低证据：恢复说明、25 条 manifest 与人工边界复核。
- 风险：规则覆盖不足产生漏报。
- 回滚边界：发现问题即隔离相关提交/分支并轮换受影响秘密；不传播文件。
- 初始状态：不完整。

### WB-004 验证恢复完整性
- 业务描述：证明恢复内容既与来源一致，也具备当前可重复验证能力。
- 可验证 AC：manifest 全量校验通过；允许来源对比通过；当前仓库测试在云端通过并绑定 commit。
- 依赖：002、003、103、104。
- 最低证据：哈希结果、云 CI run、当前测试清单；历史 31 个测试不能替代。
- 风险：只验证文件哈希却遗漏行为回归。
- 回滚边界：保持恢复 tag 不动，修复仅进入新分支。
- 初始状态：不完整。

## P1 GitHub 与云开发

### WB-101 建立个人私有 GitHub 仓库
- 业务描述：建立源码唯一事实源并保留恢复历史原点。
- 可验证 AC：直接回读 Private、默认 main、首个且唯一恢复 commit、恢复 tag；另证明 GitHub App 仅授权该仓库。
- 依赖：003。
- 最低证据：仓库 API、commit 列表、ref/tag 对象、App 安装范围。
- 风险：仓库暴露、unrelated history 或 App 权限过宽。
- 回滚边界：不改首 commit/tag；只撤销后续分支或 App 授权。
- 初始状态：不完整。

### WB-102 配置仓库保护
- 业务描述：确保 main 只能经评审和通过检查的 PR 更新。
- 可验证 AC：保护/规则集可回读；直接 push 与绕过必需检查的负向验证被拒绝。
- 依赖：101。
- 最低证据：规则 API 与安全的负向验证记录。
- 风险：管理员绕过或规则未覆盖 main。
- 回滚边界：规则变更可单独撤销，不改历史和 tag。
- 初始状态：缺失。

### WB-103 建立 Codex Cloud 环境
- 业务描述：让开发只在授权云环境发生，办公电脑不参与构建。
- 可验证 AC：环境绑定目标私有仓库；能从 main 创建隔离任务并产出可追溯分支。
- 依赖：102。
- 最低证据：环境配置回读和一次无业务改动的云任务记录。
- 风险：环境访问过宽或使用非事实源代码。
- 回滚边界：删除/禁用云环境，不改仓库历史。
- 初始状态：缺失。

### WB-104 建立基础 CI
- 业务描述：为每次 PR 提供云端、可重复的最低质量门禁。
- 可验证 AC：PR 触发检查；结果绑定 commit；失败阻止合并；不依赖办公电脑。
- 依赖：102。
- 最低证据：workflow 定义、成功与失败 run、保护规则联动。
- 风险：检查形同虚设或泄露秘密。
- 回滚边界：回退 workflow 提交，不关闭 main 的基本保护。
- 初始状态：缺失。

### WB-105 建立 Codex/Claude 协作规则
- 业务描述：明确设计、实现、评审、证据和用户 Gate 的责任分工。
- 可验证 AC：规则入库并被两类代理读取；禁止自动合并、自动发布和越权取数。
- 依赖：103、104。
- 最低证据：规则文件、一次按规则执行的 PR 记录。
- 风险：双代理互相引用汇报形成伪证据。
- 回滚边界：规则版本随 PR 回退，不追溯改写旧证据。
- 初始状态：缺失。

## P2 Sites Gate 0

### WB-201 唯一私有 Sites 项目
- 业务描述：只保留一个长期在线且私有的 Workbench 项目。
- 可验证 AC：项目唯一、访问模式私有、所有者和项目 ID 可回读，无第二长期环境。
- 依赖：105。
- 最低证据：Sites 项目列表和访问策略回读。
- 风险：误建重复项目或公开访问。
- 回滚边界：停用新版本，保留唯一项目身份。
- 初始状态：缺失。

### WB-202 建立 D1/R2 逻辑资源
- 业务描述：为 control 数据和明确 cloud-safe 产物建立隔离资源。
- 可验证 AC：D1/R2 绑定唯一项目；职责和命名可回读；R2 不承载业务表。
- 依赖：201。
- 最低证据：资源绑定、schema/对象策略与数据边界评审。
- 风险：双事实源或 local-only 数据上云。
- 回滚边界：空资源可解绑；有数据后按逻辑导出和引用关系处理。
- 初始状态：缺失。

### WB-203 验证浏览器身份
- 业务描述：确认用户浏览器只能以正确身份访问私有页面。
- 可验证 AC：授权身份成功；未授权/退出身份被拒绝；不泄露机器入口。
- 依赖：201。
- 最低证据：正负访问记录和身份声明回读。
- 风险：页面误公开或会话混淆。
- 回滚边界：收紧访问策略或回退应用版本。
- 初始状态：缺失。

### WB-204 验证 Hermes 双层机器身份
- 业务描述：机器调用同时通过 Sites 边界和应用机器身份，且只允许 Hermes。
- 可验证 AC：无凭证、单层凭证均失败；双层身份成功；办公 Node 不能直接调用。
- 依赖：202。
- 最低证据：安全探针的状态码矩阵与服务端审计摘要，不记录 secret。
- 风险：任一层可被绕过或凭证下发到 Node。
- 回滚边界：撤销机器凭证/入口，不影响浏览器身份。
- 初始状态：缺失。

### WB-205 验证 D1 迁移
- 业务描述：证明控制面 schema 能从空库按版本建立且可重复判断状态。
- 可验证 AC：空库迁移成功；重复执行安全；版本可回读；失败不留下半迁移状态。
- 依赖：202。
- 最低证据：迁移日志、schema 版本和失败回滚演练。
- 风险：不可逆 schema 或手工漂移。
- 回滚边界：按迁移合同回退应用/逻辑恢复；不预定 ORM。
- 初始状态：缺失。

### WB-206 正式启用前空白基线
- 业务描述：生产启用前确认业务表无探针和合成残留。
- 可验证 AC：除迁移元数据外业务数据为空；探针主键与清场结果可回读。
- 依赖：204、205。
- 最低证据：启用前只读计数、探针清场回执。
- 风险：测试数据污染正式事实源。
- 回滚边界：只删除已登记合成主键，不做宽范围清库。
- 初始状态：缺失。

### WB-207 Sites 应用回滚
- 业务描述：出现应用问题时可恢复上一已知良好版本而不改写业务历史。
- 可验证 AC：版本可枚举；回滚后身份和健康检查正常；D1/R2 不被覆盖。
- 依赖：204、205。
- 最低证据：隔离回滚演练及前后版本 ID。
- 风险：应用/schema 不兼容。
- 回滚边界：只切应用版本；数据恢复另走 208。
- 初始状态：缺失。

### WB-208 D1 备份恢复
- 业务描述：在应用回滚之外恢复控制面逻辑数据并验证一致性。
- 可验证 AC：可导出、隔离恢复、校验关键关系并记录恢复点；不预定频率。
- 依赖：206、207。
- 最低证据：逻辑导出、隔离恢复结果、记录数与约束校验。
- 风险：恢复覆盖正确数据或与 R2 引用不一致。
- 回滚边界：恢复前保留可返回点；不得直接覆盖唯一在线库做首次演练。
- 初始状态：缺失。

## P3 产品合同

### WB-301 API 路由与版本合同
- 业务描述：为页面、Hermes 和机器调用建立稳定、可演进的业务入口。
- 可验证 AC：版本前缀、错误结构、身份类型和废弃规则明确；未知路由拒绝。
- 依赖：105。
- 最低证据：审定合同、契约测试和路由清单。
- 风险：客户端绕过版本或错误语义漂移。
- 回滚边界：保留上一兼容 API 版本；不承诺 Kanban 兼容。
- 初始状态：缺失。

### WB-302 业务空间核心对象
- 业务描述：定义“我的工作”中的 WorkItem、Run、Interaction、Node、AgentRuntime 与 Artifact。
- 可验证 AC：对象归属、唯一 ID、生命周期和关系明确；不含 Kanban/TaskRepository 长期边界。
- 依赖：301。
- 最低证据：领域合同、schema 与 API 契约测试。
- 风险：旧 Kanban 标识继续成为核心依赖。
- 回滚边界：回退新 schema/API；不迁移旧 lf-workbench/xlf 数据。
- 初始状态：矛盾。

### WB-303 Workbench 产品空间核心对象
- 业务描述：定义产品自观察、Proposal 草稿和 Release 追溯对象，并与个人工作隔离。
- 可验证 AC：Proposal 默认无授权；接受、PR 合并、生产 Release 分属用户 Gate。
- 依赖：301。
- 最低证据：对象/权限矩阵、Gate 契约与负向测试。
- 风险：Workbench 自我授权或跨空间读写。
- 回滚边界：停用 Workbench 写入口，不影响“我的工作”。
- 初始状态：缺失。

### WB-304 状态机与人工 Gate
- 业务描述：让运行、审批、Proposal 和发布的每次状态变化可解释、可拒绝。
- 可验证 AC：合法转换和终态明确；Gate 绑定唯一对象；重放/越级/过期请求被拒绝。
- 依赖：302、303。
- 最低证据：状态图、转换表、正负契约测试。
- 风险：重复审批、越级发布、终态复活。
- 回滚边界：状态事件只追加补偿，不改写审计历史。
- 初始状态：不完整。

### WB-305 Artifact 数据分类
- 业务描述：每个产物先分类，再决定留在本地或进入 R2。
- 可验证 AC：四类数据可选；未声明默认 local-only；不做自动脱敏；secret 永不成为 Artifact 内容。
- 依赖：302、303。
- 最低证据：分类 schema、上传拒绝测试和对象策略。
- 风险：误把办公上下文标为 cloud-safe。
- 回滚边界：撤销云端引用并隔离对象；不自动删除本地原件。
- 初始状态：不完整。

### WB-306 只通过业务 API 访问
- 业务描述：所有调用方使用同一业务规则，避免页面或 Node 直写底层资源。
- 可验证 AC：页面/Hermes 仅走 API；Node 只连 Hermes；无客户端 D1/R2 凭证和直连代码。
- 依赖：304、305。
- 最低证据：依赖扫描、权限配置、网络负向测试。
- 风险：旁路写入破坏状态机和数据边界。
- 回滚边界：关闭旁路凭证/入口，回到上一 API 版本。
- 初始状态：矛盾。

## P4 可靠性与审批

### WB-401 审批投递确认
- 业务描述：审批结果只有在目标 Node 明确确认接收后才标记已投递。
- 可验证 AC：已决定、待投递、已投递分离；丢包可重投；确认绑定 Interaction 和 Run。
- 依赖：405。
- 最低证据：协议测试、丢包重试和重复确认测试。
- 风险：用户看到已批准但 Node 未收到。
- 回滚边界：可重置投递状态，不反转用户决定。
- 初始状态：不完整。

### WB-402 Node Outbox
- 业务描述：Node 离线或发送失败时保留待发 control 事件并安全重试。
- 可验证 AC：落盘后发送；确认后移除；重启不丢；local-only 正文不入队上云。
- 依赖：405。
- 最低证据：本地持久化、崩溃恢复和边界测试。
- 风险：事件丢失、无限重放或泄露本地内容。
- 回滚边界：保留可导出的本地队列；协议版本可回退。
- 初始状态：缺失。

### WB-403 Node 自动重连
- 业务描述：网络中断后 Node 自动恢复与 Hermes 的唯一机器通道。
- 可验证 AC：有界退避、重新鉴权、恢复顺序、无并发重复会话；不直连云资源。
- 依赖：402、405。
- 最低证据：断网/恢复/凭证失效场景测试。
- 风险：重连风暴或旧会话并发执行。
- 回滚边界：可停用自动重连并保留人工启动路径。
- 初始状态：不完整。

### WB-404 启动对账
- 业务描述：Hermes 或 Node 重启后对齐未完成运行、投递和 Outbox 状态。
- 可验证 AC：识别双方缺口；不猜测本地结果；冲突进入 uncertain/人工处理。
- 依赖：401、402、403、405。
- 最低证据：双方分别重启及同时重启的对账测试。
- 风险：重复执行或错误宣布完成。
- 回滚边界：暂停派发，保留原事件与人工修正入口。
- 初始状态：缺失。

### WB-405 全链路幂等
- 业务描述：重复请求、消息和回调不会产生重复业务结果。
- 可验证 AC：创建、派发、事件、审批投递、产物登记均有稳定键和同结果重放；冲突载荷被拒绝。
- 依赖：302、304。
- 最低证据：各入口重复/乱序/冲突测试与唯一约束。
- 风险：重复任务、重复发布或覆盖错误对象。
- 回滚边界：幂等记录随业务历史保留；仅回退代码，不清键。
- 初始状态：不完整。

### WB-406 WorkItem 聚合和 kind
- 业务描述：以 WorkItem 汇总需求、缺陷、任务和调查，不再借用 Kanban 卡片。
- 可验证 AC：kind 受控；子运行和审批可聚合；查询不依赖 kanban_task_id。
- 依赖：302、304。
- 最低证据：领域/API 测试和禁止词/依赖扫描。
- 风险：旧标识渗透新模型。
- 回滚边界：回退新聚合版本，不做历史数据迁移。
- 初始状态：矛盾。

### WB-407 取消和过期
- 业务描述：用户能安全取消未完成工作，系统能处理过期审批和租约。
- 可验证 AC：取消/过期有终态；与完成竞争时只有一个结果；副作用不明进入 uncertain。
- 依赖：302、304。
- 最低证据：竞态、重放和副作用状态测试。
- 风险：任务表面取消但仍在执行。
- 回滚边界：不复活终态；需要继续时创建新 Run。
- 初始状态：不完整。

### WB-408 多审批无歧义
- 业务描述：多个待审批项时必须指定对象，避免极简命令误批。
- 可验证 AC：多项时裸 `/lf y|n|s` 全部拒绝并提示使用显式 ID；唯一一项时才允许极简命令。
- 依赖：401、407。
- 最低证据：源码/契约测试覆盖零个、一个、多个及并发变化；不重复真实最终验收。
- 风险：批准错误对象。
- 回滚边界：关闭极简命令，保留显式 ID 命令。
- 初始状态：矛盾。

## P6 发布

### WB-601 云端生成 Node 发布包
- 业务描述：只在云 CI 从 GitHub commit 构建可安装 Node 包。
- 可验证 AC：构建不依赖办公电脑；包绑定 commit、CI run、版本和清单。
- 依赖：102、103、104、105。
- 最低证据：可重复云构建、材料清单和包哈希。
- 风险：非事实源代码或不可重复依赖进入包。
- 回滚边界：废弃该构建产物，不改 Node 当前版本。
- 初始状态：缺失。

### WB-602 发布包签名和校验
- 业务描述：公司电脑安装前能验证包来源与完整性。
- 可验证 AC：云端签名；Node 经 Hermes 取得包并校验；篡改、错版本、未知签名均拒绝；算法后定。
- 依赖：601。
- 最低证据：正向验证与三类负向测试、密钥边界评审。
- 风险：私钥泄露或只校验哈希不校验来源。
- 回滚边界：撤销受影响签名身份并回到已信任版本。
- 初始状态：缺失。

### WB-603 Hermes 镜像 GitHub Release
- 业务描述：Hermes 为办公 Node 提供经用户 Gate 的 Release 镜像入口。
- 可验证 AC：Release 绑定 tag/commit/包哈希/签名/用户 Gate；Hermes 不重新构建包。
- 依赖：602。
- 最低证据：Release 元数据与 Hermes 镜像一致性校验。
- 风险：镜像与 GitHub Release 漂移。
- 回滚边界：停止分发问题版本，保留原 Release 审计。
- 初始状态：缺失。

### WB-604 公司电脑只读升级
- 业务描述：公司电脑只下载、验证和安装，不开发、不构建、不 push。
- 可验证 AC：Node 无仓库写凭证；升级只经 Hermes；安装记录版本和验证结果。
- 依赖：603。
- 最低证据：权限/网络检查和一次隔离升级演练。
- 风险：办公机获得开发凭证或绕过 Gate。
- 回滚边界：停止升级通道，维持当前已验证版本。
- 初始状态：缺失。

### WB-605 Node 双版本回滚
- 业务描述：Node 保留当前与上一已知良好版本，失败时快速回退。
- 可验证 AC：切换原子化；健康失败自动/人工回退边界明确；本地上下文不迁移不丢失。

- 风险：两个版本同时运行或状态格式不兼容。
- 回滚边界：仅切 Node 程序版本，不改 D1 历史和本地工作区内容。
- 初始状态：缺失。
