# v0.5.0-trusted-loop-rc1 冻结说明

这是 Service→Node→本机 WS 可信业务闭环的仓库级冻结候选，不是部署、安装或生产发布授权。

## 包含

- 以 Task 为中心的耐久业务闭环：DRAFT、READY、显式 start、Run、REVIEW、人工 accept/request changes、DONE 和 ARCHIVED。
- Node 直接使用 OpenCode 原生 HTTP/SSE Server API：Session、一次 Mission prompt、event stream、status/messages reconciliation、permission/question、abort 和 reattach。
- Node 本机 `executionProfile` 受信验收；Runtime idle 与业务 acceptance 分离，未配置或无法证明时 fail closed。
- Session、绝对路径、原始事件、完整 stdout/stderr、diff 和验收报告只保留在 Node；Service 不回连 Node。
- 同源 Web Task 池、详情、关注页和 Service 重启后的耐久投影。
- 旧 CLI、固定三 Turn、`lingfeng.terminal`、摘要 JSON 扫描和 terminal proxy 验收路径已从当前实现删除。

## 已知边界

- 这是一个真实 canary 加确定性回归闭环，不是长期稳定性认证。
- 默认 acceptance profiles 为空；业务必须在 Node 本机登记受信 profile，否则结果为 UNKNOWN。
- 仍需连续多个真实开发 Run、真实 permission、活动 Run 跨 Node/WS 恢复和受控 SSE 故障恢复。
- 本机 vendor WS 属于 OpenCode 能力体系，但不保证与官方 `1.18.19` 逐字段一致；Node 必须继续执行 endpoint、version 和 capability Gate。
- 冻结不授权部署、安装、生产写入、凭证变更或删除历史资产。
